# aweshare 设计哲学1：谁出算力，谁来用，谁来守门

![aweshare](../../logo/logo.png)

这是一个常见的朋友圈：有人有闲置显卡，有人的订阅额度用不完，也有人两样都没有。最直接的共享方式是把 API key 发给对方，但谁都会犹豫：把 key 交出去，等于交出了整串钥匙；超额使用、泄露或账号被封，后果都要自己承担。

aweshare 将这件事拆分为三个角色：提供算力的人、使用算力的人和守门的人。本文不讲安装和命令，只说明每个角色负责什么、边界在哪里，以及背后的设计理念。

## 生产者：有算力的人

如果你有一张闲置显卡，或一份用不完的订阅，在 aweshare 中你就是生产者。你只需要做一件事：将想共享的模型「上架」。电脑上的小程序会主动连接中转站，并将模型登记到目录中，例如「老王/qwen 大模型」；之后朋友便可按这个名字调用。

这个角色的体验由三条边界决定：

- **钥匙不出门。** 你的 API key、订阅凭证，从始至终留在你自己的电脑里。别人调用时，请求被转回你的电脑，由你电脑上的程序拿着钥匙去敲上游的门。别人从头到尾看不到钥匙——连中转站也看不到。
- **你的电脑无需对外开放。** 这是一条由你主动发起的出站连接，像打电话，而不是开一家店铺。无需公网 IP、端口映射或修改防火墙；家里的笔记本、公司内网中的台式机，都可以成为生产者。
- **护栏由你设定。** 同时服务多少人、每天最多使用多少、总共放行多少，都由你在上架时写明。电脑关机或模型下架后，共享会立刻停止；需要时随时可以重新上架。

一句话：生产者共享的是**能力**，不是**钥匙**。别人能用你的模型，碰不到你的账号。

## 消费者：要算力的人

你缺一张好显卡，或是不想为一个偶尔才用的模型再开一份订阅——在 aweshare 里，你是消费者。

这个角色的使用体验刻意保持简单：拿到令牌（一串字符）和地址后，填入你原本就在使用的工具——Claude Code、Codex，或任何支持自定义接口的客户端——再在模型栏填写目录中的名称，就完成了。无需安装新软件，也无需学习新协议。共享模型的使用方式与任何 API 供应商无异。

你看不到的内容，与能使用的功能同样重要：你看不到任何人的 key、提供者的真实地址或其他人的流量。你能看到的只有目录——谁共享了什么、是否在线，以及额度还剩多少。

## hub 运营者：守门的人

中转站（hub）需要有人运营，而运营者负责的事并不复杂：

- **发邀请。** 进门凭邀请码，一人一码，用一次作废。没有码，谁都进不来。
- **看电表。** 谁用了多少、什么时候用的，账目一清二楚，公平与否有据可查。
- **踩刹车。** 有人滥用时，可以限流或挂起——这些操作都可逆、可随时撤销，也不会删除历史记录。

还有一条必须如实说明的边界：**从中转站经过的所有流量，运营者在技术上都看得到。** 这不是被隐藏的缺陷，而是公开写明的架构事实。解决方式也很直接：中转站代码完全开源，任何人都可以自行搭建。若你不信任别人守的门，就自己守一扇。项目作者也运营着一个社区版（`https://aweshare.wehuman.top`）；不信任它的读者随时可以自建。

## 设计哲学

三个角色背后，是几条贯穿 aweshare 的设计原则。

**共享能力，不共享钥匙。** 这是最核心的一条。钥匙给出去就是全给，收不回来；aweshare 把它换成按次、按量、随时可收回的能力。生产者的损失上限是「别人用掉的额度」，而不是「整个账号」。

**连接始终由生产者主动发起。** 生产者的电脑只建立出站连接，中转站从不回拨。这一设计让「共享」不再要求「一台暴露在公网的服务器」；家用宽带和公司内网都能提供算力，这是多数共享方案难以做到的。

**准入即权限，护栏即管理。** 权限模型只有一句话：获得准入，就能使用目录中的所有能力。没有授权树，也没有角色配置页。公平不靠逐项审批，而靠限额：每个模型、每位用户的用量上限都明确可见；触及上限会被清楚拒绝，并说明原因。

**诚实的边界胜过漂亮的承诺。** 中转站看得到流量，aweshare 不假装它是加密通道，而是明确写出边界、公开代码，并把自建的选择交给你。协议不匹配时会得到清楚的报错，而不是被悄悄转换成错误结果。挂起是可逆的；该说明的都放在明处。

**只记账，不留内容。** 每个请求记一行账：谁、用了哪个模型、多少字、多久。内容本身一行不存。账目够算清公平，内容不该被留下。

## 三个角色怎么碰头

最常见的场景是一群朋友：一个人提供显卡运行开源模型，一个人共享用不完的订阅，其余的人各自拿一个令牌来使用。守门人可以是其中任何一位，也可以直接使用社区版 hub。整套系统的安装和日常管理都可以交给 AI 智能体——你说需求，它来执行；只有启动常驻程序这件事，必须由你亲自在自己的终端中完成。

在这套协作中，没有人需要在群里传递 key；除守门人外，也没有人需要购买服务器。每个人的退出成本都接近零：生产者关闭程序，消费者删除两行配置，仅此而已。
